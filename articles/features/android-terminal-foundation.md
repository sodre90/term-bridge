## Summary

The foundation of the Android app's phone client: the original app-wide plan (navigation, screens, mTLS auth, the render-grid based terminal renderer) plus two focused follow-on efforts on the terminal view — a readability/UX hardening pass (fonts, colors, zoom, scrollback, keys, reconnect) and a bug-fix effort ("surface id") correcting which id the app must use to open a live terminal WebSocket. See [overview](../overview.md) and [android-app](../components/android-app.md) for the shipped, current state of this app.

## Body

### Motivation

**App foundation:** a native Android app talking only to `term-bridge` (never cmux internals) to list sessions, drive a live terminal, and let the user answer agent prompts, with FCM push. The bridge's documented HTTP/WS contract was to be the only API surface, authenticated by client-certificate mTLS plus a per-device bearer token (later replaced by e2e-encrypted bearer-token-only auth, see [pairing-e2e-encryption](./pairing-e2e-encryption.md)).

**Terminal view enhancements:** the terminal view already worked end-to-end but was not comfortable to use — it estimated columns/rows from a guessed cell size rather than a measured one, only handled `fg/bg/bold` styling, used a small monospace font with horizontal scrolling, and had no scrollback/follow behavior, pinch-zoom, or reconnect path. Live read-only WebSocket probes confirmed: style colors arrive as hex strings, both terminal and agent surfaces stream a render-grid, all observed frames were full replays with zero scrollback rows on the idle sessions probed (so populated scrollback and incremental partial frames were never actually observed at design time), and some surface ids' terminal streams closed immediately with no frame — traced to duplicate entries in the sessions list, which is exactly the bug the surface-id fix later root-caused properly.

**Terminal surface id fix:** opening an agent-type session from the app produced a persistent "Terminal disconnected" with no frame ever arriving. Agent-side instrumentation pinned the root cause: the app was opening the terminal endpoint using a **workspace id**, but the underlying replay RPC only accepts a **terminal-surface id**. cmux's workspace-list RPC actually returns workspaces that each nest a `terminals[]` array of separate, individually streamable surfaces; the bridge's original parser walked the whole payload and collected every object carrying an id and a working-directory field — both workspaces and their nested terminals — into one flat, ambiguous list, labeled by a fragile title heuristic that didn't track which ids were actually streamable. This produced both the disconnect bug and duplicate list entries.

### Design decisions

**App structure and navigation.** Single Gradle module, Kotlin + Jetpack Compose (Material 3), package `com.sodre90.cmuxremote`, minSdk 26 / targetSdk 35, JDK 17 toolchain (JDK 21 later required specifically for unit tests, due to a `lazysodium-java` test dependency — noted in this repo's own build instructions). Four screens: Sessions, Terminal, Inbox, Settings (later replaced by the pairing flow, see [pairing-e2e-encryption](./pairing-e2e-encryption.md)). Data layer split into DTOs mirroring the bridge JSON exactly, a pure render-grid model + parser, a settings store, an mTLS client builder, a REST client, and Flow-based WebSocket wrappers. Firebase/FCM is optional at build time — the Gradle plugin applies only when `google-services.json` exists. Explicitly out of scope for the foundation: create/close sessions, file-diff viewing, multiple Macs, biometric lock, tablet layouts.

**Terminal rendering approach.** The chosen architecture ("Approach A") hardens the existing decode→model→Compose-Text pipeline rather than switching renderers. A custom Canvas renderer was rejected (loses Compose's native text selection, more code, overkill at these grid sizes); an xterm.js-in-WebView approach was rejected (would need a raw PTY byte stream, which the app doesn't have — it only receives cmux's already-decoded render grid). The view was decomposed into small, independently testable units: terminal colors (decoupled from the app's Material theme so the canvas stays consistent regardless of light/dark mode), a bundled Nerd Font for glyph coverage, pure geometry/zoom math, a style resolver, the grid view itself, the screen composable, the view model, and the decoder. Cursor rendering inverts the target cell's colors rather than absolute positioning, so it survives scroll/selection; hidden when not visible, bar/underline styles downgrade to block, blinking explicitly deferred. Follow/scrollback: the decoder gained scrollback-line decoding using the same span layout as visible rows; each full frame is treated as authoritative with no incremental-delta merge (explicit YAGNI, revisit only if incremental frames are actually observed); a scroll-position heuristic re-pins to the new bottom if the user was already near it, otherwise a jump-to-bottom button appears. Fit-to-width sizing measures the bundled font's real glyph advance at the current zoom level, derives cell dimensions, computes columns/rows, and calls resize — debounced so a resize only fires when the dimensions actually change; horizontal scrolling was removed entirely since the app resizes cmux to its own column count and cmux reflows to fit. Pinch-to-zoom maps accumulated pinch scale to a clamped font size (7–22sp), driving a new cell size, new dimensions, and a debounced resize — normal terminal-resize semantics. Copy uses a native long-press selection (feasible once horizontal scroll was removed); paste is an explicit button; a scrollable key bar covers Esc, Tab, Ctrl-C/D/Z, arrows, PageUp/PageDown, Home/End. The input model is deliberately line-based + keys + copy/paste, not raw per-keystroke streaming — a stated user choice, not a technical constraint. Reconnect cancels and relaunches the socket collection, resetting to a loading state, with an error UI offering a reconnect button.

**The surface-id concept and its fix.** The core ambiguity: a workspace id and a terminal-surface id look identical (both UUID-shaped, both with id/cwd fields) but are not interchangeable — only a terminal-surface id is accepted by the terminal-replay RPC. The fix stops conflating the two: the bridge's session parser now walks the JSON tree but collects only objects carrying a `terminals[]` array — that array is what distinguishes a genuine workspace from its nested terminal surfaces. This single check eliminates both the duplicate-entry bug (panes no longer leak into the top-level list) and the wrong-id bug (the app only ever sees ids that are real, streamable surfaces once it descends into `terminals[]`). The `/sessions` response envelope was renamed from a `sessions` array to a `workspaces` array (the route path itself is unchanged). The kind-classification heuristic is demoted to purely cosmetic (still labels each pane as agent/terminal for a UI badge) but no longer decides which ids are streamable — every id under `terminals[]` is guaranteed real by construction. The app UX uses a hybrid workspace list with accordion drill-in, chosen over a flat list or a separate panes endpoint: terminals are returned inline in `/sessions` (one request, one loading state); a workspace with exactly one pane opens it directly on tap; multiple panes expand in place; a zero-pane workspace renders but is non-tappable, so the app never navigates to a dead id.

**UX tradeoffs and explicit non-goals** recorded across these docs: no raw per-keystroke input mode; no wide-character-width handling (not observed live at design time; the decoder keeps width-1 layout — later confirmed correct and not a bug, see [enhancement-audit](../enhancement-audit.md)); no incremental-frame merge; no 256-color palette (only hex colors observed, though the style resolver is structured so a palette lookup could slot in later); no blinking cursor. Also deferred for the surface-id work: sorting/pinning workspaces or panes, group rendering, and wiring unread status into a richer attention badge.

### Implementation notes

**Foundation DTOs.** Original: `Session(id, cwd, title, kind, needs_attention)`, `EventFrame(...)`, `TerminalDown/Up`, `FeedReply`. Surface-id fix replaced `Session`/`SessionsResponse` with `Workspace(id, cwd, title, preview, hasUnread, terminals: List<TerminalPane>)`, `TerminalPane(id, cwd, title, focused, ready, kind)`, and `WorkspacesResponse` — matching the bridge's Go structs field-for-field.

**Render-grid parsing.** The decoder reads columns, rows, cursor, row spans (row/column/cell_width/style_id/text) and a styles table, laying spans into a dense cell matrix with blank-filled gaps. The enhancement work extended it to also lay out scrollback spans over scrollback rows using the same layout routine. All decoder/parser tests are pure JSON-in/assert-out JVM tests, no Robolectric, no Compose UI harness needed for the pure logic.

**Auth and networking (as originally built).** An mTLS client builder presenting an imported client cert and injecting a bearer token on every request, tested against OkHttp `MockWebServer` with client-auth required and an in-test self-signed CA, asserting both authorized-success and no-cert-rejected. A REST client and Flow-based WebSocket wrappers for events and terminal streams, built via TDD against `MockWebServer` including its WebSocket-upgrade support. (This mTLS-client-cert design was later superseded by bearer-token-only auth once e2e encryption shipped — see [pairing-e2e-encryption](./pairing-e2e-encryption.md).)

**Terminal-view specific implementation.** A plain data holder for terminal colors, decoupled from the app theme, using a dark palette; a style resolver mapping style flags (inverse/faint/bold/italic/underline/strikethrough) to Compose text styling; pure, clamped geometry/zoom math (columns 20–400, rows 5–200, font 7–22sp); a label→escape-sequence key map built from character code points rather than pasted raw control bytes, since raw control bytes are invisible in source and get silently stripped by editors/tools, producing wrong assertions; a bundled Nerd Font (OFL-licensed, adding an estimated 2–4MB to APK size, license recorded under `THIRD_PARTY_LICENSES/`); the grid view rewritten around a solid dark background, a selection container plus a scrollable column of one no-wrap Text per buffer line, with per-line span-grouping and cursor special-casing, plus the stick-to-bottom/jump-to-bottom logic. The view model gained `reconnect()`; the WebSocket wrapper's message handler was changed to log dropped/malformed frames instead of silently discarding them. The screen composable was rewritten to wire cell measurement, pinch-zoom gesture detection, debounced resize, the scrollable key bar, a paste button, and a reconnect button on the error state.

**Surface-id fix implementation.** The bridge's session parser was replaced with workspace/pane parsing functions that recursively walk the decoded JSON tree, emitting a workspace for any map node with both an id and a not-yet-seen `terminals` array, recursing into children for nested groups; panes map each terminal object, skipping entries without an id. The sessions handler now calls the workspace-list RPC, parses with the new function, and writes the `{"workspaces": [...]}` envelope. Bridge tests were rewritten around a realistic nested fixture (a workspace duplicated across a groups array and the top-level array, a multi-pane workspace, a zero-pane workspace), asserting correct dedup, no pane-id leakage into the top-level list, and correct field mapping. On the app side, the new DTOs were wired through the REST client, a new pure-logic file provides a "single pane" resolver and a pane-count label formatter (each independently unit tested), the sessions screen was rewritten around a workspace-card → pane-row hierarchy with tap-to-open or expand-to-drill-in behavior, and the navigation callback for opening a terminal changed from taking a full session object to taking a raw surface-id string. The agent-side terminal handler needed no change — the fix is purely about the app/bridge always passing a genuine terminal-surface id.

**Testing approach (consistent across all four docs).** Strict TDD with JUnit4: write a failing test, confirm it fails, implement, confirm it passes, commit. Pure logic (parsers, decoders, geometry, style resolution, key maps, the workspace parser) carries essentially all the test weight; Compose UI is kept thin over it and verified either by compiling or, for the terminal-view work, by manual on-device verification against a running emulator covering: dark canvas with correct glyph rendering, no horizontal scroll, visible block cursor, pinch-zoom reflow, key bar scrolling, paste, live-output follow behavior with scrollback, and reconnect behavior on an instantly-closing secondary surface.

### Status

The two spec documents carry explicit, self-reported status lines: the terminal-view-enhancements spec is "Approved direction; pending user review of this spec"; the terminal-surface-id spec is "Approved (ready for implementation plan)." The plan documents don't carry an equivalent field, and their task checklists remain unchecked as written. The original app plan has no `Status:` line but closes with an `## Execution` section stating, in the past tense, that it was executed inline with the test/build commands as the verification gate, a commit per task, plus a self-review marking every spec requirement complete — indicating the plan's author treated it as executed, though the individual task checkboxes in the file itself remain unchecked template form. The terminal-view-enhancements plan has no execution/completion summary and closes with implementer notes flagging scrollback row indexing as "the one unconfirmed assumption," to be confirmed on-device during the plan's own final task — i.e. the plan itself frames that detail as unverified as written. The surface-id plan has no `Status:` line and closes with a self-review section that verifies the plan's own spec coverage and type consistency, not that the tasks were actually executed.

Beyond these self-reported markers, none of the five documents contain merge references or other confirmation of final shipped state within the documents themselves; [overview](../overview.md) and [android-app](../components/android-app.md) describe the resulting features (fit-to-width, pinch-to-zoom, wrap toggle, D-pad, the workspace→panes model) as part of the current, live app, which is later external evidence beyond these five documents alone.
